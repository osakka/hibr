# Checker migration observations

Baseline: Hibr commit `7bfde28` (0.99.506), before this branch's changes. The existing checker answers were captured before editing and compared with inspection-backed function discovery and signatures.

- `deps.py`: definition sets are identical across the desktop; its suite passes with 32,118 checked lines and no failures.
- `census.py`: six former definitions (`sum`, `avg`, `min`, `max`, `count`, `__eval`) disappear from the desktop definition set. They are text in Sheet's quoted `SS_PRELUDE` heredoc, not definitions executed when that source file is read. Existing definitions retain their original file mapping.
- `census.py` signatures: `dt_putruns` is added. Its multiline declaration was missed by the old one-line regex.
- `strictvars.py`: 3,130 strict functions are checked instead of 2,972. The extra 159 real definitions include inline helpers and `dt_putruns`; the heredoc's `__eval` is no longer treated as a desktop definition. The suite still reports no failures. Removing missed-function bodies from top-level scanning also removes false global allowances. Its variable analysis has since moved onto `vars` too; see below.
- `540-examples.t`: duplicate names and callback arity consume producer records, and arities/registrations come from conventions.json. The record-based version passes the recorded examples suite.

These are reviewed differences in structural coverage, not silent attempts to force a parser to reproduce regex mistakes. Private parser provenance now passes the exact-span regressions and extraction/reinspection for all 3,289 function records. The interface and extra private instrumentation still require upstream review.

## Required release review: dependency calls and references

Compared `ef6e412`'s token-based dependency checker with producer `calls` and `refs` on the same 98 installable files. `python3 tests/inspect_deps_parity.py ef6e412` reports **99 old, 99 new, 99 unchanged cross-entry candidate locations**: no removed or added edges to explain. Both complete checkers report zero dependency failures. The production checker has no `TOK` pattern; only the explicit audit loads the historical Python checker from Git.

The new checker supplies the known installable function names to `refs` as an explicit `symbols` whitelist. This requests literal candidate names, not cross-file resolution: records remain syntax, say `lookup: supplied-symbol`, and remain unresolved. Without that option, refs retains its inspected-file-only scope and privacy. The module does not read other source files. It never reveals unrelated argument literals. Calls and refs supply the line and enclosing function, including inline definitions and nested substitutions.

The line counter changes from 32,118 to 34,099 because it now includes 1,981 declaration lines formerly skipped wholesale. This is a reporting difference; the candidate-location comparison above is unchanged. Guard arguments and sourced library paths have since moved onto `calls --arguments`, and own-location paths onto `vars` (see below); catalogue-header recognition stays a text check, since a header comment is not code. Variable facts have become the `vars` request.

## strictvars.py on `vars` (Gitea #536)

`strictvars.py` read what a function writes with seven regular expressions (`ASG`, `BIND`, `READ`, `FOR`, `PRV`, `ARI`, `DECL`) over lines with their quoted text blanked; it now asks `vars`, and which files say `strict` from `calls`. Before the regexes went, both answers were compared over every strict desktop function -- `python3 tests/inspect_strictvars_parity.py 174fcb86` loads the regex checker from Git and prints each difference -- as the set of (file, line, name) each says is written there and not declared local or a parameter -- before the top-level and shell-name allowances, so a difference hidden by them still counts:

- **6,867 old, 7,396 new, 6,740 the same.**
- **127 only in the old**, each a false write: 116 `IFS=... read` and 4 `HIBR_PROCNAME=... term open` prefixes the old `prefix()` heuristic did not recognise as prefixes; 6 `env LC_ALL="$l" locale ...`, where `LC_ALL=` is an argument to `env`; 1 `declare -gx LANG` after `&&`, which `DECL` only matched at the start of a line.
- **656 only in the new**, each a real write the old missed: 568 assignments `prefix()` took for a command's prefix because the value held a blank (`$((a + 1))`, `${z% *}`); 36 writes after a `declare -gA` or `-gx` in the same function, which `declared()` called local because it looked for `-g` as a whole word (the shell lets a function write a name it has just declared with `-g`; the checker, before as now, wants every global a strict function writes declared at file level, and each of the 36 is); 40 `json`, 2 `arr` and 2 `mapfile` targets and 1 `{DT_ERR}>&2`, forms no pattern knew; 6 `read -r NAME`, whose option pattern took `NAME` for `-r`'s argument; 1 `PE["r"]["$s"] := ...`, a bind with a quoted key.
- **Top-level writes**, which allow a name everywhere: 1,943 old, 1,933 new. 13 only in the old were not variables at all (`''`, `&`, `)`, `Video/audio.hibr]`, Sheet's prelude heredoc's `__a`, `__e`, `__n`, `__o`, `__s`, and `k`, `s`, `str` from text the old read as top-level code), each a false allowance; 3 only in the new are real (`{as_e}>&2` in lib/appstub.hibr, `{err}>&2` and an `if ... hl=$(...)` in lib/ctl.hibr).

Three differences were the producer's, found by this comparison and fixed in it, each with a fixture row in `tests/inspect_vars.py`: a rest parameter (`...pairs`) was not `declared: param`, so writing it read as a global (`dt_buttons`, `dt_dlgbtns`); a type word was skipped anywhere in a declaration, where the shell takes one only as the first name, so `local -A qr qc map` did not declare `map` (`dt_winsfit`); and `{name}>&-`, which closes the descriptor the variable holds, was a write where it is a read. With those fixed both checkers report no failures over 3,386 functions. Planting a function that writes `ZZ=$((1 + 2))`, `json parse ZZ_J` and `read -r ZZ_R _` in a strict file -- three globals the shell refuses there -- fails the new checker three times and passes the old.

## Call arguments: deps.py and 540-examples.t (Gitea #537)

`calls --arguments` gives the argument words of the commands a consumer names, and the last text readings of call arguments moved onto it.

- **540-examples.t**'s two awk programs -- no window's `_open` opens its own kind, and every app's bar begins File, then Edit -- are `inspect_checks.py opens` and `menus`. Which prefixes are windows comes from the `registration` records conventions.json already produces, not from a second reading of `dt_app`/`dt_new`. Against the awk's set at 174fcb86 the `dt_app` prefixes are identical; of `dt_new`'s, the awk had five that were not prefixes (`$hs_prefix`, `$n`, `$note`, `\`, `return`, the last word of a line) and missed two (`native`, `stickies`, whose `dt_new` has an argument after the prefix or continues on the next line). The menus check reads every `dt_menu` and `dt_editmenu` call in the function, where the awk read only a line that began with one. Planting `dt_new ... zzp "$arg"` in `zzp_open` and `[ -n "$id" ] && dt_menu "Zz"` in `zzp_menus` fails the new checks and passes the awk; the cases the awk caught, both still fail. Both refuse to pass when they find nothing to check, which is what a producer older than `--arguments` gives.
- **deps.py**'s `GUARD` and `LIBSRC` are the arguments of `command`, `dt_has`, `dt_needs`, `.` and `source`; `OWNPATH` is a `BASH_SOURCE` read whose own bytes are `${BASH_SOURCE%/*}` followed by `/..`. `${0%/*}` is still matched in the text, since `vars` leaves positional parameters out. At 174fcb86 the guards were 433 regex matches and are 405 call records, 404 the same: the 29 only in the regex are a variable's name taken from a dynamic argument (`command -v "$t"`, `dt_has "${pane}_draw"` read as guarding `t` and `pane`, never an installable function), and the 1 only in the records is `dt_needs ... pw-mon`, which the regex cut at the dash. Libraries sourced: 10 and 10, the same; own-location paths: none either way. Planting a `source` of an unmarked library and an `echo "dt_has fb_relist"; fb_relist` fails the new checker twice and passes the old.

## Formatting oracle

After the required semantic changes and before the one-statement-per-line rewrite, `python3 tests/inspect_oracle.py capture build/inspect-format-oracle` captured raw `-j` bytes for all four requests over all 197 tracked Hibr files (788 outputs). The same script's `compare` mode checks every byte and the source corpus hashes after the rewrite. `gcc -fsyntax-only -Wall -Wextra -Iinclude mods/inspect/inspect.c` also passes. These are formatting checks; the endline/default/binding changes are intentionally covered by separate behavioral regressions.

The inspection fuzzer now preflights loading the selected producer and requires an inspection JSON result for every non-crashing case. `HIBR_TESTMODS` is explicitly mapped to the shell's module path. A missing module can no longer produce a false clean fuzz result. The required-change verification reruns 300 cases with the actual ASan/UBSan producer and leak detection.
